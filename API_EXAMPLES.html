Every request and response on this page is captured output — status codes, byte counts, timings, ETags and headers come from the run that produced this file.

Step 2GET /v2/files/{fileRef}
Resolves the reference and returns the file itself.

What to know before reading

AuthenticationA client key derived from your registered email buys a one-hour bearer token at POST /v2/auth/token. The key is never accepted on a data route, so the standing secret crosses the wire once an hour rather than on every call.
Requested as if liveThe data is simulated, but the endpoint behaves like a production one: results come back newest first and you bound a request with dates the way you would against a real system.
No future dataEvery query is capped at the instant the request arrives. A record dated after that is not hidden or refused — from the caller's side it does not exist, and it becomes available as time passes. Upper bounds past the present are clamped; a future range returns an empty result, not an error. Every response carries asOf.
Two steps, alwaysGroup records are metadata only and never contain a payload. The fileRef is an opaque HMAC-signed token — it carries no path, no row id and no filename, and altering one byte makes it invalid.
Report groupsThe daily terminal reports are returned directly as JSON. No file reference is issued for them.
Time boundsfrom/to are inclusive — a bare date as the upper bound means end of day. since is exclusive, so incremental readers never re-read the last record. order=asc walks forward through history.
No internal detailNo database identifier, table, path or internal filename appears in any response. The acceptance test greps for them and asserts zero.
